# Donor search for the AKLT spectral-gap formalization

Research snapshot: 15 November 2026, America/New_York; some API timestamps are 16 November UTC. This is a source-level literature review, not a build or an axiom certification. No Lean executable, Lean build, agent, or GitHub write was used. “Direct import” below means a suitable theorem exists at the donor's own pin; cross-version compatibility has not been tested.

The best starting points are **QICLean/TNLean for projections, coherent tensors, Knabe and AKLT examples; Physlib for explicit sl₂ tensor decomposition; the public fluctuations-palomar package for finite reversible chains; TauCeti for sphere measures and moments; and HexPosDefTheory for checked exact matrix positivity**. Mathlib already supplies FKG, four functions, spectral decomposition, conditional expectation, and walks. There is substantial reusable infrastructure, but no inspected donor closes this manuscript's full spin-2 square-lattice argument.

The largest unresolved mathematical imports are the manuscript-specific SU(2)/polynomial identification and edge-divisibility lemma, its particular spherical 4-designs, the Martinelli–Olivieri–Schonmann route from window estimates to box gaps, the stronger boundary-connectivity statement in Appendix B, and the trail/pair recursion. The matrix checker itself has a much better donor than a fresh Bareiss implementation. The H3 memory-walk certificate remains a major computational design problem, even after those imports.

## 5. Kernel-checked computation without native_decide

### What is actually accelerated

The inspected Lean kernel explicitly recognizes natural-number literal operations: successor, add, truncated subtract, multiply, power, gcd, division/remainder, Boolean equality/order, bitwise and/or/xor and shifts. This is visible in `type_checker::reduce_nat` in [src/kernel/type_checker.cpp](https://github.com/leanprover/lean4/blob/0747cc27c914be223c797293f82099071d4619d1/src/kernel/type_checker.cpp). Natural numbers use the efficient bignum runtime (normally GMP), rather than expanding numerals as unary successor chains. The same source has size checks for computed numerals: arbitrary precision is not permission for unbounded intermediate growth.

**There is no corresponding list of primitive `Int` reductions in that function.** Integer computations benefit through their reductions to accelerated Nat operations, but constructor/sign handling and generic typeclass code still cost reductions. Likewise `Rat`, `Finset`, matrices, arrays and balanced-map interfaces do not inherit their compiled-code complexity in kernel reduction. This is why a Nat-oriented encoding and proved conversion lemmas matter. The historical [Native high-performance arithmetic? thread, April 2021](https://leanprover-community.github.io/archive/stream/113489-new-members/topic/Native.20high-performance.20arithmetic.3F.html) discusses the GMP trust boundary; the current kernel source is the stronger evidence for the exact primitive list.

`decide` builds a proof from a Decidable instance; ordinary elaborator reduction can duplicate work. `decide +kernel` takes the kernel-checking route directly; see [src/Lean/Elab/Tactic/Decide.lean](https://github.com/leanprover/lean4/blob/0747cc27c914be223c797293f82099071d4619d1/src/Lean/Elab/Tactic/Decide.lean). It does not make every recursive algorithm efficient or remove kernel stack/memory limits. Hex's [HexMatrixTheory/Literal.lean](https://github.com/kim-em/hex-dev/blob/3a1b9813b1d1876ae0c89f5cfc20da05547bd854/HexMatrixTheory/Literal.lean) is a particularly useful implementation example: `decideProof` builds `of_decide_eq_true`, and `addClosedProof` checks an auxiliary closed theorem once. Candidate production may use compiled code; its output is accepted only after a kernel-checked equality/Boolean certificate and a soundness theorem. That is compatible with the requested standard.

### Recommended checker architecture

This is a proposed design, not a claim that the AKLT certificates have already been checked in Lean.

1. **A small specification layer, separate from certificate search.** Define the graph, spin/frame weights, pattern equivalence, exact moment contraction, matrices, trail automaton, and the claimed inequalities in ordinary mathematical types. Prove one connection from each executable checker to that specification. External Python/C, solvers, floating-point eigensolvers and power iterations may choose witnesses; none may supply an assumed theorem. Keep the theorem surface in a Mathlib-only Challenge or equivalent independently inspectable definitions, following [README.md](https://github.com/leanprover/comparator/blob/865edc14486c3388e9225daa971da8e157488c3e/README.md).

2. **H1: use checked congruence/triangular witnesses first.** Try H's `pos_def` and, for stored certificates, `Int.checkPositive_sound`/`positive_of_scaled`. The manuscript already mentions an independent congruence-plus-diagonal-dominance route; that is a natural alternative to repeated determinant computation. Clear rational denominators once with a proved positive scale. Certify matrix construction, symmetry, changes of basis, annihilated antisymmetric sectors and coverage of all required sectors. A proof that a supplied numeric matrix is PosDef does not prove it is the matrix obtained from the local integral.

3. **If Bareiss is needed, check an elimination transcript.** Reuse Mathlib/Hex decomposition invariants and prove each exact-division update by an integer identity and nonzero pivot condition. Do not trust a language's division result merely because it is an integer. Existence of Mathlib's LDL decomposition assumes PosDef and therefore cannot be used circularly to establish it. Split stage/row/entry equalities into bounded closed lemmas; compose them with a general soundness proof. Modular residues alone do not establish positivity unless accompanied by bounds and a proved reconstruction argument.

4. **Check pattern coverage independently.** Enumerate the finite local status rules, establish the quotient/reflection reductions, then check that the certificate table covers every class at its required straight/turn threshold. The manuscript reports 106,101 raw configurations and 7,962 classes. Checking 7,962 arbitrary rows without this completeness theorem would leave H1 unproved. The FKG closed-form route can reduce computation for 4,735 classes, but only after its pruning/classification theorem is connected to the enumeration.

5. **H2: certify a positive test vector and sparse row inequalities.** Work with `M₈ h ≤ λh`, checking positive rational/dyadic entries of h and cross-multiplied inequalities. Prove the window automaton enumerates the intended edge-simple trails and that quotienting to 938 dihedral classes preserves the relevant operator. The generator's approximate Perron vector is only a candidate. For trail growth the manuscript's power-domination argument needs no numerical eigenvalue solver and no irreducibility hypothesis. Check `λ ≤ (98075/100000)^8` by exact arithmetic.

6. **H3: certify monotone upper envelopes of sparse recurrences.** At each time/block, supply dyadic upper bounds and check that they dominate the correctly generated predecessor sums; after rules stop, check the **left** inequality `z W ≤ λz`, positivity of z, and `V₂₆₀ ≤ a z`. Reuse a proved finite-sum/rounding lemma rather than trusting `fesetround`, IEEE doubles, C integer overflow assertions, or the printed table. Preserve the mode-A/mode-B time cutoffs, boundary deletion and response phases. Prove the geometric tail bound once and finish its scalar inequalities exactly. The uncompressed window×position×phase state space is very large; streamed blocks and symmetry reductions with proved coverage are essential candidates for a future feasibility benchmark.

7. **Choose executable representations for kernel reduction.** Use Nat-packed finite labels/bit sets and fixed-denominator dyadic endpoints where possible, with proved codecs to readable structures. Avoid per-step `Finset.univ`, long `Fin.cases` matrix literals and repeated Array traversal. Store and kernel-certify shared transition tables once. For signed quantities use an explicit, proved signed-Nat or dyadic layer; do not assume compiled Int/UInt/array performance is kernel performance. LeanCert's `roundOut_contains` and `mem_mul` are ready semantic building blocks; Hex's one-check auxiliary-lemma path is a useful model for batching.

8. **Keep replay bounded and strict.** Shard by pattern, matrix block, automaton row and time slice. Each shard proves a closed proposition with `decide +kernel` or an equivalent kernel-checked reflected proof. Use strict LeanCert kernel mode; if using NativeTrust, use the no-fallback route and examine generated theorem dependencies. Re-run Comparator with only `propext`, `Classical.choice`, `Quot.sound` permitted, and inspect the final target's transitive axiom set. Intentional Challenge holes, unrelated library axioms, generated native axioms and replacement definitions must not enter the Solution proof closure.

The first future performance experiment should contain one largest H1 matrix **and its matrix-construction bridge**, one representative sparse H2 row block, and one bounded H3 recurrence block. Measure kernel replay time and peak memory separately from candidate generation and elaboration. This report does not promise that all H3 data will fit the registry's verification budget; that requires measurements on the actual data, which were outside the permitted bundle-reading scope here.
