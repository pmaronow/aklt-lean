# H1 finite certificate library

H1 proves the pointwise covered-pattern inequality used by the spectral-gap
argument. The generated library has **7,964 owner modules**, **414,638 theorem
axiom audits**, and **25 module kinds**, covering 7,962 patterns and 12,173 blocks.
Its public closing contracts are exact and hypothesis-free:

```lean
CertData.H1.Close.finiteData : AKLT.Blueprint.Top.H1FiniteDataStatementV2
CertData.H1.Close.certificate : AKLT.Blueprint.Top.CertificateStatement
```

The closing proofs use only `propext`, `Classical.choice`, and `Quot.sound`.
`CertData.Close.All` combines them with the H3 contracts and the analytic proofs.

## Inputs and generation

The numeric inputs are `index.json` and sixteen compressed integer-witness
chunks. File names, byte counts, and SHA-256 pins are listed in
[the artifact guide](../ARTIFACTS.md) and `verification/inputs/H1.json` at the
repository root. `H1_INPUT_DIR` selects their directory; its default is
`data/h1/` under the repository. The input location is independent of
`H1_REGEN_ROOT`, which selects the generated-output root for scratch exports.
`H1_REGEN_REPORT` selects the report directory, defaulting to
`verification/runs/H1/` under the repository. Explicit `--report-dir` options
retain precedence in commands that provide them.

The numeric route exports every pattern, geometry, coverage condition,
representative index, and witness, then bundles independent declarations into
owner modules. It emits 158,230 logical components before bundling. Every owner
agreed byte-for-byte with the independently converted module-system source,
including the exact owner/dependency/component map. The conversion changes
visibility and identifier spelling while preserving numeric and string data,
arithmetic expressions, and check statements.

## From-scratch commands

Run from the repository root after the hand-written dependencies and pinned
Mathlib cache are available. Use an empty generated-source destination and a new
report/scratch directory:

```sh
export PATH="$HOME/.elan/bin:$PATH"
export H1_INPUT_DIR="$PWD/data/h1"
export H1_REGEN_REPORT="$(dirname "$PWD")/aklt-verification/H1"
mkdir -p "$H1_REGEN_REPORT"
python3 AKLT/Cert/H1/tools/production_receipts.py inputs \
  --output "$H1_REGEN_REPORT/data-input-receipt.json"
python3 AKLT/Cert/H1/tools/production_reexport.py \
  --scratch "$H1_REGEN_REPORT/export-scratch" --install \
  --report-dir "$H1_REGEN_REPORT"
python3 AKLT/Cert/H1/tools/production_build.py \
  "$H1_REGEN_REPORT/data-only-production.json" \
  --jobs 12 --cap-gib 7 --ram-gb 160 --report-dir "$H1_REGEN_REPORT"
python3 AKLT/Cert/H1/tools/production_receipts.py verify \
  "$H1_REGEN_REPORT/data-only-production.json" --report-dir "$H1_REGEN_REPORT"
python3 AKLT/Cert/H1/tools/production_close.py --report-dir "$H1_REGEN_REPORT"
```

These are also the built-in H1 steps of `scripts/cold-verify.sh`. No adapter or
separate prerequisite script is required. `lake build Handwritten` supplies the
hand-written modules that the generated family imports. The samples
`RegenSamples.H1Consumer` and `RegenSamples.H3Consumer` test the exposed interfaces.

Without `--install`, `production_reexport.py` compares the fresh numeric export
with already installed source bytes. `production_build.py` resumes only successful
receipts whose source, recursive dependency, compiler/build pins, and compiled
artifact hashes still match. `--force` repeats the selected reductions. Generated
sources remain ordinary `.lean` files under `CertData/H1/Generated/Batch/` and
`Bridge/`; the runner does not compact sources unless explicitly requested.

## Resources and measurements

The builder permits up to 36 Lean processes and defaults to a 270 GB aggregate
reservation/RSS limit. `--ram-gb` can lower that limit without changing receipt
keys. `--cap-gib 7` is the default per-process choice in the commands above;
the plan retains 16 GiB reservations for larger data/assembly owners and 64 GiB
for the two terminal owner kinds. The available-memory floor is 40 GB and the
free-disk floor is 100 GiB. Each compilation uses one Lean worker in a fresh
process. The complete driver adds its requested outer RSS limit to both families.

The final build checked every owner and exported theorem from the numeric inputs:
152.483 CPU-hours, 4.407 wall-hours at 35 processes, 5.896 GiB peak module RSS,
and 157.252 GB peak sampled aggregate RSS. Python export and scheduling overhead
are excluded from the compiler CPU total. No module was reused from an earlier
build. The verified receipt is `H1/verified-production.json` in the release
receipts; its summary and per-kind totals are tracked in `verification/final/H1/`.

## Receipts, artifacts, and closing

The append-only `events.jsonl`, per-module `receipts/`, separate stdout/stderr and
GNU-time files in `logs/`, and per-theorem `.axioms.json` files record commands,
source hashes, dependency keys, all compiled artifact parts, exit status, CPU and
wall time, RSS, exact theorem names, and axiom sets. The independent verifier
checks the whole owner DAG, actual imports, hashes, successful exit status, and
complete axiom transcripts. `SOURCES.sha256` pins every generated source;
`COMPILED.sha256` pins all 23,892 compiled artifact parts. `verified-production.json`
contains the per-kind totals and complete accepted records.

`production_close.py` builds `CertData.H1.Close.Main` and `CertData.H1.Close.Audit`,
checks both exact closed contracts, and records `closing/receipt.json`,
`closing/SOURCES.sha256`, and `closing/COMPILED.sha256`. Each printed axiom set is
restricted to the three permitted axioms.

The deterministic source archive is `H1-module-sources.tar.gz` (25,987,925 bytes),
SHA-256 `a27c7dc50ccf88bf53ddeb1d739764eebe623c763bc31ec3f34fd521af9c543f`.
It contains exactly the 7,964 generated source paths and no compiled objects.
The [artifact guide](../ARTIFACTS.md) gives its installation command. Direct
compilation publishes normal `.olean`, `.olean.private`, and `.olean.server`
artifacts in `.lake/build/lib/lean/`; Lake trace files are not synthesized, so an
ordinary `lake build` can repeat numerical reductions. The closing steps use
`lake env lean` to consume the checked objects. No dependency update or Mathlib
source build is part of these commands.
