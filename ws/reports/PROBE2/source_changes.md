All writes for this study are under `AKLT/Probe2/` or the PROBE2 report directory. No dependency, manifest, toolchain, project configuration, or Mathlib source was changed. No sub-agents were used.

The original probe files and README were copied from `/home/ubuntu/aklt/compfeas/probes/`. `source_changes.json` records original hashes and copy-time hashes. `source_inventory.json` records final hashes of every local Lean source.

The first runner revision captured source byte size at completion, before start-time SHA capture was added. The first failed guard/data processes had already read the original source when the on-disk identifier repair was made; their byte-size fields can therefore describe the repaired file. Their error logs identify the original `guard` source, whose exact bytes/hashes remain in the original directory and copy manifest. Later records capture the source SHA at process start. Historical syntax-helper failures are described below; current files contain the corrected versions.

Changes to copied files:

* `Baseline.lean`: retained `import Mathlib`; added `Elab.async=false`, `checked : True := by decide +kernel`, and `#print axioms checked`.
* `BellmanGuard1/16.lean`, `Bellman9Guard1/16.lean`: renamed the identifier `guard` to `guardMask` in its declaration and uses. Mathlib already declares root `guard`. No numerical parameter or checker operation changed. The first two runs and the first data-only diagnostic had already read the pre-repair source; their nonzero exits and `sorryAx` outputs are rejected, retained measurements.
* Every other supplied Lean file and the copied README are unchanged. Async checking is disabled on the Lean command line.

New definitions and variants:

* `PackedLiteralSyntax.lean` supplies `packed_hex%`: untrusted elaboration validates a lower-case hex string, decodes it by balanced range splitting, and emits one ordinary `Expr.lit (.natVal ...)`. The decoder uses byte indexing, leaves of at most 16 digits, and structural fuel 64. It adds no kernel reduction rule. Kernel obligations refer to the emitted literal. The first draft incorrectly used `Syntax.getString`; it was fixed to `isStrLit?`. An unused experimental chunk-merging helper was removed, and the initial character-list decoder was changed to byte indexing to avoid large per-character allocation. The initial helper compilation failures are recorded. The final version has no `unsafe`, `extern`, `implemented_by`, axiom, opaque declaration, sorry, or native proof tactic.
* `FastBellmanGuard*`, `FastBellman9Guard*`, `FastPacked*`, `FastBellmanData`, and `FastLiteral*`: replace each `0xDIGITS` token by `packed_hex% "DIGITS"`, and add the syntax-module import. All digits and all checker expressions are unchanged. Extra guard counts 128, 1024, 4096 and packed counts 1024, 4096 change only the iteration literal. `BellmanData` drops the routing/checker declarations and uses a trivial theorem to diagnose loading; its first run used the pre-repair guard name.
* `Literal1/10/50MB`: one Nat literal with exactly 1,000,000 / 10,000,000 / 50,000,000 binary bytes, expressed as twice that many hex digits. The repeating digit pattern is `d3a75c19e826b04f`. A kernel theorem checks its remainder modulo 65536. `FastLiteral*` uses the same digits through the elaborator above. `ImportLiteral*` imports the corresponding successful Fast module and independently kernel-reduces the same remainder. This tests representation, not a certificate predicate.
* `IntRowsSyntax.lean` supplies untrusted `int_rows%` and `int_row%` elaboration, emitting ordinary `List` and `Int` constructors from comma/pipe-separated integer strings. `FastH1Gram` has exactly the supplied matrix, factor and checker, with the two list literals replaced by these constructor expressions. `H1RowData` further splits the same two lists into 131 named rows each, under namespace `H1Rows`; `H1RowCheck` imports those lists and retains the original factor/checker/theorem. No Gram arithmetic or entry changed. A prototype refactor needed an explicit `liftMetaM` for `mapM`; the failed support/data/import attempts before this repair are retained in the logs. An older valid syntax olean was used by the successful FastH1Gram run; the later valid helper preserves its encoding and adds the row form.
* `Nat*Double`, `Int*Double`: change only the original loop count to twice its value; widths, seeds and moduli are unchanged.
* `KernelAnd64/256/4096/16384`, `KernelShift64/256/4096/16384`: small supplemental kernel equalities on deterministic bit patterns. They diagnose built-in arithmetic behavior and are not AKLT checks.
* `Parallel1` through `Parallel6`: byte-identical copies of `FastBellmanGuard1024`, with distinct module paths, used in fresh sequential and concurrent processes.

`run.py`, `limit_exec.py`, `inner_limits.json`, `parallel.py`, and the report-generation scripts are measurement infrastructure, not proof evidence. Every numerical theorem is checked by normal Lean using `decide +kernel`. All proposed certificates remain untrusted inputs until those predicates and their mathematical soundness theorems are checked.
